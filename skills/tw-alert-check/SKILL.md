## 2. 流程
凌晨說「明天」（1.2.45，整體流程鎖串 P14 甲案，總召同意）：使用者在台北時間 00:00～05:59 說「明天」時，今天白天與明天白天兩天都給，並寫明各是幾月幾日（例：「今天白天 11/09、明天白天 11/10」）；不只挑一天，也不只寫「明天」不寫日期。取不到台北當下時間時，當下時間標 UNKNOWN，同樣兩天都給；日期以使用者訊息或官方預報頁標示的日期為準，兩者都沒有就兩天的日期都標 UNKNOWN，不猜。
0. 使用者說官方網站或工具「連不上」「失敗」「卡住」時，回覆在對齊行之後先列七欄困難卡（現象｜證據｜類別｜影響哪個 AC｜解除條件｜負責方｜首次發現時間）再查；本輪自己讀得到時仍列卡，類別照原本會判的寫，解除條件寫「已解除（本輪取得成功，附證據）」（同 manus-core §2.7；1.2.43，整體流程鎖串 P10）。
1. 先查中央氣象署有沒有颱風警報或特報（豪雨、強風、低溫等）。
2. 有警報或特報，就查人事行政總處與該縣市政府的停班停課公告，寫出公告時間。尚未公告就寫「截至 HH:MM 尚未公告」，不推測。
3. 官方頁讀不到就標 NOT_RETRIEVED，附官方連結請使用者自行確認；不得用新聞代替官方結論。
4. 之後才回答天氣細節與活動。有警報時推薦戶外活動或夜間演出，必須註明可能取消，請查主辦單位公告。
5. 交通：陸上颱風警報或強風特報期間，不建議騎乘兩輪車；優先大眾運輸，並查營運公告。

## 3. 輸出順序
第一段固定寫：警特報狀態（含發布時間）→ 停班停課（含公告時間或 NOT_RETRIEVED）→ 天氣 → 活動或交通建議。數字與狀態附行內標籤，最後一行寫流程鎖（同 manus-core §5 第 1、5 點）。
日期行寫在第一段之後、流程鎖之前（1.2.49）。引用的每個官方來源各寫一行日期「發布：YYYY-MM-DD｜生效：YYYY-MM-DD｜查閱：YYYY-MM-DD」，缺的寫 UNKNOWN，三項都要出現；警特報的發布時間、停班停課的公告時間接在同一行後面；讀不到（NOT_RETRIEVED）的來源也寫這一行，查閱寫本次日期，其餘寫 UNKNOWN，並在同一行寫「找過：官方頁網址（NOT_RETRIEVED）」（1.2.48；依 manus-core §4 與 references/research-and-dating.md，細節以本節為準）。
