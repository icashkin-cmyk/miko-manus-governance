# 知識卡-固定格式與驗收

## 1. 問問題

判斷使用者是否要求建立、修改、整理、升級或展示知識卡。出現「知識卡」「K01～K50」「任務卡」「卡片格式」「卡片模板」即觸發本 Skill。確認卡片名稱、適用情境、內容目的、是否為新卡或既有卡升級、狀態、編號、保存位置與授權範圍。知識卡不是 MIKO 正本，也不是 Skill；若與正本衝突，以正本為準。

## 2. 解決

| ID | 類型 | 觸發條件 | 操作要求 | 禁止事項 | 驗收證據 | 失敗處理 |
|---|---|---|---|---|---|---|
| KC1 | J | 觸發知識卡需求 | 建立或讀取卡片基線，確認編號、名稱、狀態、既有版本、目標路徑與完整需求。 | 不得猜測編號、覆蓋既有卡或把卡片當正式 Skill。 | 原卡路徑、索引、版本、狀態與需求摘要。 | 資訊不足標 `UNKNOWN` 或 `NOT_READ`，先補讀或停止。 |
| KC2 | P | 已確認卡片範圍 | 依固定格式輸出：`# KNN 知識卡名稱`、`狀態：`、`名稱`、`在以下情況下使用`、`內容`；內容內固定包含【目的】、【執行要求】、【禁止事項】、【完成與失敗判定】。建立或修改後執行 `python3 -c "from pathlib import Path; p=Path('<card>.md'); t=p.read_text(encoding='utf-8'); required=['名稱','在以下情況下使用','內容','【目的】','【執行要求】','【禁止事項】','【完成與失敗判定】']; assert all(x in t for x in required); n=len(t.split('## 內容',1)[1].replace('\n','')); print(n); assert n<=1000"`，檢查固定欄位與內容字數。 | 不得省略五段、任意改名、把 Skill 四節格式套入知識卡，或加入未授權正式規則。 | 完整 Markdown、編號、狀態與內容欄字數。 | 缺段落或格式衝突時修正候選，不得宣稱合格。 |
| KC3 | C | 卡片草稿完成 | 在【執行要求】寫清觸發關鍵詞、語意判斷與具體步驟；在【完成與失敗判定】寫 PASS、必要證據、UNKNOWN、NOT_RUN、BLOCKED 的處理。 | 不得只寫抽象口號；不得把未執行、未知或阻塞寫成 PASS。 | 格式檢查、內容欄字數、觸發與狀態判定檢查。 | 任一必要欄缺失標 `REWORK_REQUIRED`，保留失敗證據並重測。 |
| KC4 | J | 既有卡片要升級 | 採累積式演進：保存舊版、Hash、來源與 diff，繼承有效內容後再補強；新卡或升級卡列入索引與狀態。 | 不得覆蓋歷史版本、刪除既有有效內容或把候選標為已採用。 | 舊版快照、修改前後 diff、索引、字數與狀態證據。 | 無法確認是否保留時標 `UNKNOWN`，保留原內容，不刪除。 |

## 3. 後設

知識卡固定是三個外層段落加一個內容區：名稱、在以下情況下使用、內容；內容區固定再分四個標題。不可把知識卡、Skill、MIKO 正本混為同一層。知識卡的作用是提供 Manus 可直接套用的任務提示，不會解除 manus-core 的停止、暫緩、硬禁止、權限或唯一寫入者規則。

## 4. 檢查

- expected：每張卡都有名稱、狀態、適用情境、目的、執行要求、禁止事項、完成與失敗判定；觸發詞與具體操作清楚，狀態可判定。
- forbidden：缺少固定段落、只寫摘要、把知識卡當 Skill、把候選當正式採用、以文件存在冒充實測、覆蓋歷史卡片。
- 相近反例：一般 Skill 建立但未提到知識卡；單純展示既有卡片；沒有卡片格式需求的普通問答；只修改正本 Skill。
- AC-01：檔頭為 `# KNN 知識卡名稱`，且有 `狀態：`。
- AC-02：存在「名稱」「在以下情況下使用」「內容」三個固定段落。
- AC-03：內容包含【目的】【執行要求】【禁止事項】【完成與失敗判定】四個固定欄位。
- AC-04：【完成與失敗判定】明確處理 PASS、UNKNOWN、NOT_RUN、BLOCKED。
- AC-05：既有卡升級保留原版、Hash、diff 與狀態；未經授權不得刪除或覆蓋。

## 0.2 累積式整合、衝突與邊界路由

本 Skill 的優化、升級、重構、修正與移轉一律採累積式演進：先保存目前版本與 SHA-256，再逐項分類為繼承、強化、新增、修正、重構或廢止；未理解或未驗證的既有內容不得刪除。執行前載入 `version-evolution-preservation`，並確認本 Skill 與 `manus-core`、`independent-audit`、`three-party-review`、`ai-engineering-anti-fraud-test-credibility` 的責任不重疊。

若本 Skill 與其他 Skill、正本規則、外部來源或使用者限制衝突，不得靜默覆蓋；先標記 `CONFLICT`，保存衝突位置、影響範圍與待決事項，停在可逆狀態。任何新增能力都必須通過正向、負向、邊界、異常、回歸與必要的 Mutation 測試；`FAIL`、`NOT_RUN`、`UNKNOWN`、`BLOCKED` 不得升格為正式採用或 Runtime 生效。

本候選版本只代表 Manus 分支候選內容，不代表 GitHub main、正式採用或 Runtime 已生效。

## 累積式補強｜20 FAIL 修正候選 2026-11-17

### 完成判定與格式回歸規則
- 每張知識卡必須包含名稱、使用時機、目的、執行要求、禁止事項、完成與失敗判定、必要證據及狀態處理。
- 沒有完成判定、證據要求或 `PASS`／`FAIL`／`UNKNOWN`／`NOT_RUN`／`BLOCKED` 出口的卡片，不得正式採用。
- 格式升級必須保留舊版與逐條 mapping；回歸測試核對舊版有效規則、限制與例外未遺失。
- 提示詞：`請把規則轉成知識卡，逐欄填入使用時機、目的、執行要求、禁止事項、完成與失敗判定及證據；缺欄不得宣稱完成。`

## 累積式優化｜責任邊界、限制與衝突路由 2026-11-17

### 統一治理邊界
- 本 Skill 只負責下列 `owns` 工作；`does_not_own` 所列工作不由本 Skill 自行決定。
- 命中邊界時依 `handoff_to` 轉交，不靜默擴張責任、不覆寫其他 Skill 結論。
- 外部 Connector、付款、刪除、Push、Merge、Release、正式採用與 Runtime 啟用不因本 Skill 的領域判斷而自動授權；由 `manus-core` 管理授權、唯一 writer、讀回與回復。
- 本 Skill 可提出候選 `PASS`／`FAIL`／`UNKNOWN`／`NOT_RUN`／`BLOCKED`，但 `final_integrator` 固定為 `manus-core`；`may_adopt: false`、`may_enable_runtime: false`。
- 任務專屬禁止、STOPPED、PAUSED 或使用者當次較嚴格限制，優先於一般常設授權。
- 規則、版本或來源衝突時標 `CONFLICT`，停止相依步驟並保存原文、位置、影響、差異與回復方式；不得以替代來源繞過授權或停止條件。

| 欄位 | 本 Skill 邊界 |
|---|---|
| `final_integrator` | `manus-core` |
| `may_adopt` | `false` |
| `may_enable_runtime` | `false` |
| `external_write_owner` | `manus-core`／指定唯一 writer |
| `conflict_priority` | 任務專屬硬限制 > manus-core 一般規則 > 本 Skill 建議 |

### 本 Skill 路由
- `owns`：知識卡欄位、格式、狀態與可驗收性檢查。
- `does_not_own`：不裁決領域規則內容，不取代 Skill 正文。
- `handoff_to`：內容衝突交相關 Skill／核心裁決。


## 第五套高難度邊界與回復補強（候選升級 2026-11-18）

本節是累積式升級，不取代或刪除既有規則；本 Skill 的本次職責為：知識卡欄位、來源與採用狀態。

### 5B 多重邊界與唯一主路由
- 當同一請求同時命中本 Skill 與其他 Skill 時，本 Skill 只處理自己的 `owns` 範圍，指定唯一主路由、輔助路由與 `handoff_to`；不得雙重寫入或自行成為最終裁決者。
- 無法判定主責時標 `CONFLICT`，保存觸發規則、route chain、責任者與待決，不以猜測選路。

### 5E 部分成功與例外
- 已完成與未完成步驟必須分開記錄；部分成功不得標整體 `PASS`。來源、輸出或讀回不完整時標 `UNKNOWN`、`NOT_RUN` 或 `BLOCKED`，依實際證據判定。
- 必須保存已完成副作用、未完成範圍、stdout、stderr、Exit Code、錯誤與下一步；不得以替代來源掩蓋缺口。

### 5X 授權、停止與不可逆操作
- 一般授權不解除任務專屬限制；`STOPPED_BY_USER`、`PAUSED_BY_USER`、`BLOCKED`、使用者當次禁止與不可逆操作限制優先。
- 外部寫入、付款、刪除、發送、Push、Merge、正式採用與 Runtime 啟用須交 `manus-core`／指定唯一 writer；不得用替代路由繞過授權。

### 5R 回復、冪等與重試
- 首次失敗與回復失敗都必須保存；非冪等操作沒有去重鍵或讀回證據時，禁止重試、禁止重複寫入，停止並要求人工裁決。
- 回復須指向明確版本、檔案或狀態；保存原始錯誤、回復錯誤、部分副作用、diff、Hash 與可執行的回復步驟，不得無限重試。

### 5C 循環路由與衝突整合
- 必須記錄完整路由鏈並偵測重複訪問；發現循環或相互矛盾結論時標 `CONFLICT` 或 `BLOCKED`，在可逆狀態停止並交 `manus-core`。
- 本 Skill 不得覆寫其他 Skill 或稽核者結論；最終整合者固定為 `manus-core`，本節不授予正式採用或 Runtime 權限。
