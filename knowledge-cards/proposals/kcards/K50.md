K50｜系統生命週期與整體健康

名稱

K50 系統生命週期與整體健康

在以下情況下使用

系統定期盤點、重大版本變更、架構調整、長期維護或準備發布整體版本時使用。

內容

【任務辨識】檢查治理、知識卡、Skill、Router、工具、成果及驗收系統是否形成可維護閉環。

【執行要求】

1. 核對唯一治理核心及權限配置。
2. 盤點知識卡、Skill、Registry、Router 與相依。
3. 檢查安全、效能、版本、平台及證據完整性。
4. 確認未完成、退休、阻塞及未知項目。
5. 提出分階段改善與回復計畫，交正式責任方審查。

【Skill 路由】manus-core、independent-audit、safe-implementation。

【禁止事項】不得以文件數量或局部 PASS 宣稱整體健康；不得自行升格正式版本。

【完成判準】整體架構、依賴、Runtime、E2E、風險及未完成項目均有證據。

【失敗處理】任何關鍵層級缺少證據，整體狀態維持 BLOCKED／UNKNOWN，不宣稱完整閉環。

⸻

文件結尾｜候選狀態與後續驗收

本文件僅為 K03～K50 正文候選稿，不是 GitHub 正式檔案，也不是 Manus 已載入的知識卡。

正式使用前應逐張完成：

1. 與現有 K01～K03、K39 候選原文比對，保留原有獨特資訊。
2. 核對 MIKO 正本與 knowledge-cards/README.md 的實際規格。
3. 確認每張卡內容欄不超過 1,000 字元。
4. 核對 Skill 名稱是否存在、是否採用及是否可由 Runtime 使用。
5. 執行正向、負向、邊界及異常測試。
6. 依既有權限提交候選、獨立驗收及治理裁決。
7. 正式路徑寫入後讀回並驗證 Hash。
8. 另行驗證平台載入及真實任務 Runtime。
