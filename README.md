## 專案目的

本 repository 是從 `icashkin-cmyk/miko` 複製出的獨立 Manus 架構工作區。它用來保存 Manus 端的治理架構、Skill 整合候選、能力目錄、測試證據、歷史快照與恢復資料；原 MIKO repository 是來源正本，不在此專案內被反向修改。

本專案採累積式演進：保留來源、原始版本、差異、測試、失敗紀錄與回復路徑。新版本不因較新而自動刪除、覆蓋或宣告舊版本失效。

## 專案架構

```text
miko-manus-governance/
├── README.md                         # Manus 專案入口與目前 Gate 狀態
├── MANUS_VERSION                     # Manus 專案版本；不取代 MIKO 正本 VERSION
├── VERSION                           # 複製來源的 MIKO 版本基線，供對齊與追溯
├── governance/                       # 治理規則、角色、權限、Gate 與邊界
│   └── project-architecture/         # 本專案架構、路由與責任分層
├── skills/                           # Manus 候選／整合 Skill；每個 Skill 一個目錄
├── source-archive/                   # 各 Skill 的來源快照與保真資料
├── archive/                          # 歷史版本、退役版本與回復材料
├── migration-ledger/                 # 逐 Skill 轉移、升級、版本與驗收帳本
├── tests/                            # 驗證器、回歸、反向測試與 Mutation 測試
├── evidence/                         # 實際命令、stdout、stderr、exit code、hash 與判定
├── knowledge-cards/                  # Manus 任務卡與候選提案
├── adapters/                         # 受控的工具／Runtime 介接候選，不等於已啟用
├── projects/                         # 領域專案資料，不取代治理規則
├── handoff/                          # 收工、恢復與換手資料
└── sync/                             # 協作狀態；不作為正本或驗收替代證據
```

## 規則、任務與邊界

| 層級 | 可以做 | 不可以做 |
|---|---|---|
| `governance/` | 定義角色、權限、Gate、狀態與失敗出口 | 不得把規格文字當 Runtime 實測 |
| `skills/` | 保存候選 Skill 與其可讀指令 | 不得以檔案存在宣稱已安裝或已載入 |
| `source-archive/` | 保留來源、日期、commit、SHA-256 與差異 | 不得修改來源快照冒充原始內容 |
| `tests/` | 執行格式、正向、負向、邊界、異常、回歸、Mutation 測試 | 不得把預期輸出當實際證據 |
| `evidence/` | 保存真實命令與結果，區分 PASS／FAIL／UNKNOWN／NOT_RUN／BLOCKED | 不得刪除失敗或將部分通過寫成整體通過 |
| `archive/` | 保存歷史版本、退役版本與 rollback target | 不得因新版產生而刪除舊版 |
| `adapters/` | 設計或保存介接候選 | 不得宣稱已連線、已授權或熱插拔 |
| `knowledge-cards/` | 保存 Manus 任務卡與提案 | 不得取代 MIKO 正本、正式採用或治理裁決 |

## 驗收角色

- `IMPLEMENTER`：建立或更新候選成果，保存修改前後差異。
- `TESTER`：自行執行必要測試，保存完整命令與輸出。
- `INDEPENDENT_AUDITOR`：重新讀取目標與來源，不接受前兩者的 PASS 宣稱，重新判定。
- `GOVERNANCE_OWNER`：處理正式採用、權限、刪除／廢止與不可逆決策；本 repo 不自行冒充該角色。

## 證據狀態

`PASS` 只代表有符合條件的實際證據；`FAIL` 代表實際不符合；`UNKNOWN` 代表證據不足；`NOT_READ` 代表來源尚未讀取；`NOT_RUN` 代表尚未執行；`BLOCKED` 代表依賴、授權或決策阻塞。後三者不得升格為 PASS。

## 使用方式

1. 先讀 `MANUS_VERSION`、`VERSION`、`governance/project-architecture/` 與最新 handoff。
2. 盤點 `skills/*/SKILL.md`，建立完整清單與總數。
3. Stage 1 全部項目通過後，才開始 Stage 2 資產分類與路徑架構驗證。
4. 每個階段保存 manifest、命令、stdout、stderr、Exit Code、執行時間與 SHA-256。
5. 未通過時只修正目前 Gate，不跳站、不把候選或文件完整度當成 Runtime 完成。
